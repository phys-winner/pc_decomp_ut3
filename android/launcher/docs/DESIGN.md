# Заготовка лаунчера для статических рекомпиляций

Статус на 30.10.2026: база реализована (`android/src`, `native`, `tools`), покрыта проверками на ПК
(`tests/run_tests.py`), подключена к Unreal Tournament 3 и проверена на тестовом Pixel 10a (Android 17,
Mali-G715, страницы 16 КБ): холодный старт без библиотеки игры в `:launcher`, разрешения с объяснениями,
импорт из папки и ZIP через системный пикер и встроенный браузер, копирование и перенос, проба Vulkan,
языки, «Играть» и «назад». Подключение к игре — [INTEGRATION.md](INTEGRATION.md), обновления —
[UPDATES.md](UPDATES.md), значки — [ICONS.md](ICONS.md).

## Решения

1. Это **заготовка**, которую каждая игра встраивает в свой APK, а не «лаунчер лаунчеров».
2. **Пакет базы у каждой игры свой**: исходники лежат в шаблонном пакете `port.launcher` и при сборке
   копируются в `<пакет приложения>.launcher` (`org.ut3.port.launcher`). Чтобы общий native-код не зависел от
   имени пакета, лаунчер передаёт данные игре через окружение процесса (`PORT_*`), без JNI.
3. Зависимости — **git-подмодулями**: база подключается как `android/launcher`.
4. **targetSdk 37** (Android 17). Для LAN-игры — runtime-разрешение `ACCESS_LOCAL_NETWORK`.
5. Обновления: релизы **без pre-release**, `update.json` приложен к последнему релизу.
6. Языки: en, ru, de, pl. Без автоматического issue и без проверки версии игры (пока).
7. stronghold_crusader и the_void не меняются; первая игра на базе — UT3, вторая — homm5 (31.10.2026, по просьбе
   владельца: три издания, перенос настроек старого лаунчера, Android 8–10).

Код уже размножился и разъехался: `Deflate64.java` в homm5 и the_void идентичен, `unpack.c` отличается
только именами JNI-функций, `Zip`/`Unpacker`/`Textures`/`UnpackService` совпадают на 60–99%.

Найденные проблемы (в этих проектах не исправлялись — по решению 7):
- the_void падает, если системный пикер отключён;
- homm5 и stronghold передают состояние между процессами через SharedPreferences (`apply()` и устаревший
  `MODE_MULTI_PROCESS` не гарантируют свежесть);
- homm5 и stronghold создают новый keystore, если его нет (APK тогда не встанет поверх);
- значки homm5 (33,97 dp) и Stronghold Extreme (35,38 dp) выходят за safe zone 33 dp;
- все GitHub-релизы помечены pre-release (`releases/latest` = 404).

## 2. Устройство базы

```
launcher/
  android/src/port/launcher/   Java-шаблон (пакет переписывается при сборке)
  native/                      port_env.h (PORT_*), zipmount.c/.h (игра из несжатого ZIP),
                               vulkan_probe.c, vulkan_requirements.h (проба Vulkan-драйвера для DXVK/Turnip)
  tools/                       launcher.py (подготовка к сборке, сборка libportprobe.so), icons.py (проверка
                               значков), update_manifest.py (update.json из релизов)
  ci/update-manifest.yml       GitHub Action для репозитория игры
  tests/                       run_tests.py: Java-селфчек, тест zipmount, сборка пробы NDK, проверка инструментов
  examples/homm5.port.json     пример спецификации многодистрибутивной игры
```

**Процессы.** Лаунчер, встроенный браузер и фоновая служба — в `:launcher`; проба Vulkan-драйвера — в
`:probe`; игра — в своём процессе. Обычный выход игры возвращает в лаунчер и завершает процесс игры:
следующий старт идёт с чистого состояния. Лаунчер узнаёт Activity дистрибутивов через `PackageManager`, не
загружая классы игры, поэтому её native-библиотеки в `:launcher` не попадают.

**Передача запуска.** Состояние — маленькие property-файлы в `files/launcher/` (fsync + rename под файловой
блокировкой), их одинаково видят оба процесса. Лаунчер пишет запись запуска и стартует Activity
дистрибутива с extras (`launcher.distribution`, `renderer`, `skipIntro`); игра вызывает `Launch.attach()`, и
native-код получает пути, рендерер, опции и сведения об обновлении через `PORT_*`.

| Класс | Назначение |
|---|---|
| `LauncherActivity` | экран: шапка с версией, разрешения, дистрибутивы, файлы игры, фоновые работы, рендерер, опции, текстуры, место, обновление, «О порте» |
| `Spec` | `assets/launcher/port.json` и `build.json` |
| `Texts` | строки en/ru/de/pl, выбор языка, тексты из `port.json` |
| `Ui` | тема из токенов, карточки, кнопки, переключатель, прогресс, edge-to-edge |
| `State` | межпроцессные property-файлы |
| `Storage` | All files access, тома, SAF → путь, разрешения |
| `Pickers` + `FileBrowserActivity` | системный пикер или встроенный браузер |
| `Zip`, `Deflate64` | ZIP/ZIP64, Deflate, Deflate64 (из homm5) |
| `Install` | части дистрибутива, поиск в папках, план архива, распаковка/копирование/перенос с откатом |
| `StoredArchive` | индекс несжатого ZIP для игры без распаковки |
| `Cleanup` | категории лишних файлов, превью, удаление «всё или ничего» |
| `Gpu`, `Renderers` | возможности видеочипа и Vulkan, доступность режимов с причинами; режим без пройденной пробы не выбирается сам |
| `Probe` | служба в `:probe`: `libportprobe.so` создаёт Vulkan-устройство и проверяет то, что нужно DXVK (функции, `VK_EXT_robustness2`, BC1–3), Turnip — через adrenotools; отчёт `probe.txt` по отпечатку прошивки и сборке, зависание дольше 15 с засчитывается как сбой |
| `Updates` | проверка `update.json`, сравнение версии и подписи |
| `Launch` | запуск дистрибутива; API для игры (`attach`, `starting`, `failed`, `firstFrame`, `exited`, `language`, `openLauncher`) |
| `Work` | фоновые работы в foreground-службе dataSync |
| `PortHooks`, `TextureBackend` | точки расширения для кода игры |

## 3. Требования → реализация

| Требование | Как сделано | Статус |
|---|---|---|
| Несколько дистрибутивов и переключение | карточка и «Играть» на дистрибутив; «Вернуться в игру», если она идёт; `Launch.openLauncher()` для меню игры; части дистрибутива с фиксированными или выбираемыми папками | готово; переключение из игры — вызов из кода игры |
| Архив с несжатыми файлами без распаковки | разбор ZIP64, план, индекс `ZMI1` (`StoredArchive`), сжатые файлы — рядом (sidecar), persisted URI или путь, дескриптор → `PORT_MOUNT_FD_*`, чтение `pread`/`mmap` (`zipmount.c`) | готово; у UT3 включено с 0.8.2-dev (слой в `files.c`), проверено на Pixel 10 |
| Отключённый «Файлы»/DocumentsUI | `getApplicationEnabledSetting` для `com.google.android.documentsui` и `com.android.documentsui` → кнопка «Включить» и встроенный браузер; пикер, закрывшийся быстрее 400 мс, — тоже на браузер; переключатель «Всегда встроенный браузер» | готово |
| SAF по возможности | `OPEN_DOCUMENT(_TREE)` с persistable-правом, путь из документа, удаление архива через `DocumentsContract`; игра из архива по SAF-дескриптору работает без доступа ко всем файлам | готово |
| Обновления через GitHub + в игру | Action → `update.json` в последнем релизе; клиент сравнивает versionCode и подпись; `PORT_UPDATE_*` и плашка поверх первого кадра | готово; ждёт снятия pre-release |
| OpenGL ES / DXVK / Turnip с определением | версия Android, библиотеки в APK, Vulkan по `FEATURE_VULKAN_HARDWARE_VERSION`, Adreno по `GL_RENDERER`/SoC/`/dev/kgsl-3d0`; причины недоступности словами; native-проба драйвера в `:probe`; запуск, не дошедший до первого кадра, называется с причиной завершения (ApplicationExitInfo); отказ игры стартовать (`Launch.failed`) показывается её словами и отключает автозапуск; выбор хранится там, где его читает игра (`PortHooks`) | готово; проверено на Mali-G715 (DXVK и Turnip недоступны с причинами) |
| Уменьшение размера | категории из `port.json`, превью со списком и размерами, удаление только неизменившихся файлов, пустые папки следом; удаление архива после распаковки | готово |
| Пропуск роликов | галка `intro` дистрибутива → extra `skipIntro` и `PORT_SKIP_INTRO`; реализация — в игре | готово; у UT3 с 0.8.1-dev (`-nostartupmovies` или ролики; с 0.8.2-dev пропуск касанием и геймпадом) |
| DXT → ETC2/ASTC | карточка при отсутствии S3TC в GPU, выбор ASTC/ETC2, откат, фоновая работа; кодек и контейнер — `TextureBackend` игры | готово в базе; у UT3 нет бэкенда |
| Версия порта | шапка и «О порте»: versionName, versionCode, коммит сборки | готово |
| Ссылка на GitHub | «О порте»: ссылка, «GitHub», «Релизы» | готово, если задан `app.github` (у UT3 — `phys-winner/pc_decomp_ut3`, репозиторий ещё не создан) |

## 4. targetSdk 37: что учтено

- **Хранилище:** legacy-доступа больше нет — пути вне папок приложения требуют «Доступ ко всем файлам»
  (`MANAGE_EXTERNAL_STORAGE`); лаунчер просит его, только если папки частей лежат вне папок приложения.
- **Локальная сеть:** `ACCESS_LOCAL_NETWORK` (`Manifest.permission`, API 37, группа NEARBY_DEVICES) —
  спрашивается один раз перед первым запуском, после объяснения лаунчера («Продолжить» / «Не сейчас»);
  карточка «Разрешить» остаётся, пока не выдано. На платформах без этого разрешения проверка считает его выданным.
- **«Назад»:** на Android 16+ при targetSdk 36+ нет `onBackPressed()` и `KEYCODE_BACK` — лаунчер, браузер и
  `GameActivity` UT3 используют `OnBackInvokedCallback`.
- **Edge-to-edge** обязателен с targetSdk 35 — отступы по системным панелям и вырезу.
- **Foreground-служба:** тип `dataSync` + `FOREGROUND_SERVICE_DATA_SYNC`; уведомления — `POST_NOTIFICATIONS`:
  подтверждение первой долгой работы (импорт, текстуры) объясняет, зачем оно, и системный запрос идёт до её начала.
- **Видимость пакетов:** `<queries>` для пикеров, браузера и пакетов DocumentsUI.
- **Большие экраны:** `android:appCategory="game"` сохраняет ориентацию игры на планшетах (у UT3 уже было).
- `PendingIntent` — `FLAG_IMMUTABLE`.
