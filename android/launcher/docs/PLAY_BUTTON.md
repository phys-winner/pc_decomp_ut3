# Кнопка запуска: фон, обводка и частицы

Кнопка должна продолжать палитру игры и отличать запускаемые издания друг от друга.
Основа эффекта — реализация общей базы, которую использует Grief Syndrome через
`tools/grief_launcher.py` и `app/port.json`: скруглённый фон, тонкая обводка,
мягкое свечение, проходящий блик и шесть частиц внутри кнопки.

Цвета задаются данными. Добавлять собственный аниматор, текстуру, библиотеку или
патч с заменой цветов в сгенерированном Java для каждого порта не требуется.
Исходник общей реализации — `android/src/port/launcher/Ui.java`, класс `ActionButton`.

## Настройка общей темы

В `android/port.json` игры (для Grief Syndrome — `app/port.json`) задайте:

```json
{
  "theme": {
    "accentDark": "#8C5B88",
    "primaryFill": "#4A2948",
    "playGlow": "#E0A9D4",
    "playParticles": "#FADFF6",
    "text": "#F4EAF4"
  }
}
```

Это фрагмент спецификации: остальные разделы `port.json` сохраняются.

| Параметр | Что рисует | Значение без настройки |
|---|---|---|
| `theme.primaryFill` | Основной фон основной кнопки | `#3A2414` |
| `theme.accentDark` | Постоянную обводку толщиной 2 dp | `#9A4A16` |
| `theme.playGlow` | Полупрозрачное свечение фона и пульсирующей обводки готовой кнопки | `theme.accent`, затем `#E8742A` |
| `theme.playParticles` | Частицы и цвет проходящего блика | `theme.text`, затем `#F2F4F7` |
| `theme.text` | Надпись на готовой кнопке с эффектом | `#F2F4F7` |

Новые цвета `playGlow` и `playParticles` записываются как непрозрачные `#RRGGBB`.
Альфа для анимации рассчитывается в коде. Сборочная проверка отклоняет неверный
тип или формат новых параметров; Java дополнительно сохраняет запасные цвета.

Подбирать фон удобно от тёмного оттенка игрового акцента. Обводку делайте заметно
светлее фона, свечение — насыщенным, частицы — светлыми, близкими к тому же оттенку.
Надпись проверяйте вместе со свечением и бликом: для обычного текста ориентир —
контраст не ниже 4,5:1. Частицы малые и не должны закрывать надпись плотной заливкой.

## Отдельный стиль каждого издания

Общая база читает `distributions[].theme`. В этом объекте используются четыре
цвета кнопки: `primaryFill`, `accentDark`, `playGlow`, `playParticles`.
Каждый отсутствующий параметр наследует общую тему. Надпись сохраняет общий `theme.text`.

Например, фрагмент издания Hammers of Fate в спецификации Heroes V:

```json
{
  "id": "hof",
  "theme": {
    "primaryFill": "#163044",
    "accentDark": "#6AADD0",
    "playGlow": "#A7E2F4",
    "playParticles": "#F1FCFF"
  }
}
```

`Spec.Distribution.theme` передаётся в `Ui.button(..., Ui.PRIMARY, d.theme, ...)`.
Цвета принадлежат конкретной карточке; изменение выбранного издания не
перекрашивает остальные карточки и второстепенные кнопки. У «Вернуться в игру»
сохраняются фон и постоянная обводка издания, но нет анимации готовности.

## Как получается эффект

1. Фон рисуется обычным `GradientDrawable`, радиус углов — 14 dp, обводка — 2 dp.
   В общей базе поверх него сохраняется стандартный отклик `RippleDrawable` на нажатие.
2. `ActionButton.onDraw()` перед надписью ограничивает рисование скруглённым `Path`.
   Частицы, блик и свечение не выходят за границы кнопки.
3. Фаза `p = (uptimeMillis % 3600) / 3600` задаёт цикл 3,6 с.
   Пульсация `q = (1 − cos(2πp)) / 2` меняет альфу заливки от 12 до 34,
   а обводки — от 45 до 130 из 255.
4. Линейный блик шириной 80 dp проходит слева направо. Его края прозрачные,
   центр имеет альфу 40 из 255 и цвет `playParticles`.
5. Для каждой из шести частиц возраст `a = (p + i/6) % 1`,
   координата `y = h × (0,95 − 0,85a)`. Позиции по горизонтали распределены
   детерминированно; радиус до 1,5 dp и альфа до 190 меняются по `sin(πa)`.
   У каждой второй частицы есть короткий крестик: ледяная палитра напоминает снег,
   тёплая — искры. Физика и число частиц одинаковы у всех палитр.
6. Перерисовка запрашивается через 33 мс только у включённой видимой кнопки,
   когда окно имеет фокус. Скрытие, потеря фокуса и отключение кнопки прекращают цикл.
   Смена фокуса или видимости окна инициирует обновление.

Готовая кнопка получает эффект через `ui.attention(play, true)`. Подсказка импорта
`attention(button, false)` остаётся обычной пульсацией акцентом, без частиц.
Отключённая кнопка не рисует эффект. Если системные анимации выключены, готовая
кнопка показывает неподвижную композицию при фазе 0,25 и не запускает цикл кадров.
На Android до 8 проверяется `ANIMATOR_DURATION_SCALE`, начиная с Android 8 —
`ValueAnimator.areAnimatorsEnabled()`.

Grief Syndrome затемнён по сравнению с прежним `primaryFill: #825578`, чтобы
светлая надпись оставалась контрастной и во время прохода блика.

Stronghold и The Void сохраняют собственные лаунчеры. У них тот же способ
рисования реализован в `Theme.PlayButton` и `Launcher.PlayButton` соответственно.
Цвета хранятся в локальных `playColours()`: Stronghold получает идентификатор
карточки (`classic`, `extreme`, `stronghold`), The Void использует уже определённую
`GameActivity.Release.library` (`void`, `void_tension`) и обновляет кнопку при выборе папки.
Не определяйте версию по переведённому названию или порядку папок.

The Closing Shift по согласованной области задачи остаётся с прямым входом в Unity:
отдельной кнопки запуска в нём нет. Архивные проекты не являются рабочими интеграциями.

## Проверка и подключение

```powershell
python tools/launcher.py check --spec GAME/android/port.json
python tests/test_play_button.py
python tests/run_tests.py
```

Сборщики ищут базу через `PORT_LAUNCHER`, затем `android/launcher`, затем `../launcher`.
Обновляйте реальную копию, которую использует сборка: UT3 и Crashday содержат свои
исходники в `android/launcher`. Их локальные изменения сохраняются; перезаписывать
всю базу ради цвета кнопки не требуется. Сгенерированные `build/.../src` не являются
местом настройки. Готовые APK получают новые стили после следующей сборки.

Проверки на ПК исполняют код рисования на записывающем Canvas, проверяют палитры,
наследование, остановку кадров и формат спецификации. Для визуальной приёмки
на устройстве проверьте каждое издание, длинную локализованную надпись, выключенные
анимации и возврат из фонового режима; сборка Java сама по себе этого не подтверждает.
